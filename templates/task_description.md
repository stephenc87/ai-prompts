# Create Task Description

Turn a task, work item, or short requirement into a clear, actionable task that supports visible progress and collaboration.

## Prompt

Using the task information I provide, create a structured task description with these sections:

## Purpose

Explain why the task is being done and what understanding, outcome, or progress it should create.

## Work to complete

List the main actions required to complete the task.

Order the actions where there is a natural sequence.

## Working approach

Break the task into useful intermediate steps or checkpoints so progress can be reviewed before the final result is complete.

Where relevant, include points such as:

* initial investigation or preparation
* early draft, prototype, outline, or findings
* review or feedback point
* revision or validation
* finalisation

Do not create artificial checkpoints for very small tasks.

## Expected output

Describe the tangible result, document, decision, artefact, or other output that should exist when the task is complete.

## Dependencies

Identify related tasks, information, people, approvals, or artefacts required before or during the work.

State `None identified` where no meaningful dependency is known.

## Definition of done

List clear conditions that can be checked to confirm the task is complete.

Include intermediate review or collaboration requirements only where they are genuinely useful.

When writing the task:

* keep the language concise and practical
* use action-oriented wording
* keep the scope focused on the stated task
* make progress visible before final completion where practical
* encourage early sharing of drafts, findings, prototypes, or questions when feedback could change the work
* avoid requiring finished work before useful review can occur
* distinguish required work from optional or follow-up work
* make the definition of done observable
* do not invent requirements, dependencies, approvals, or review stages unsupported by the information provided

Task information:

Provide any relevant task title, goal, context, known work, constraints, dependencies, expected output, related tasks, review requirements, or completion requirements. This information may be structured or informal.
