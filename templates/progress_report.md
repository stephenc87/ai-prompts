# Create Progress Report

Turn project notes, completed work, decisions, current state, and remaining work into a clear progress report.

## Prompt

Using the project information I provide, create a concise progress report that clearly communicates what has been completed, what is currently in progress, important decisions, and what remains to be done.

Use the following structure where relevant.

## Progress update

Include the reporting date if supplied.

Begin with a short summary of the main focus or progress since the previous update.

## Completed or substantially drafted

List work that has been completed or progressed far enough to be meaningfully reported.

Keep each item:

* concise
* specific
* outcome-focused
* grouped where useful

Where a feature or work item has several important parts, use nested bullet points.

## Current structure or workflow

If the work involves a sequence, architecture, process, navigation model, or workflow, describe the current structure clearly.

Use numbered steps or arrows where they make the sequence easier to understand.

## Key decisions

Summarise important decisions, design choices, constraints, or principles established during the work.

Explain decisions briefly where the reasoning is relevant.

## Remaining work

List the practical work still required.

Distinguish unfinished work from optional future improvements where necessary.

## Risks, blockers, or open questions

Include known blockers, unresolved decisions, dependencies, or risks when provided.

Do not invent risks or problems that are not supported by the project information.

## Links and references

Include relevant project links, documents, prototypes, repositories, tickets, or other references supplied with the update.

## Guidance

When writing the report:

* preserve the terminology used by the project
* focus on progress rather than retelling the entire project history
* distinguish completed, in-progress, and remaining work
* keep important decisions visible
* retain useful technical or workflow detail without unnecessary expansion
* avoid overstating completion
* do not invent work, decisions, blockers, dates, or outcomes
* use headings and bullet points to keep the report easy to scan
* keep links associated with the work they refer to
* maintain a professional but straightforward tone

Project information:

Provide any relevant reporting date, recent work, completed items, current work, workflow changes, decisions, blockers, remaining tasks, links, or other project context. The information may be structured or informal.
